# 工作流开发与设计面试题库

> 面向 AI 工作流平台、低代码自动化平台相关岗位，题目同时参考扣子（Coze）、Dify 的产品形态，并结合 MeowFlow 的实际工程实践。

## 使用说明

- 难度标记：P1 为基础题，P2 为进阶题，P3 为架构与综合设计题。
- 建议用自己做过的工作流项目把题目串起来，例如 MeowFlow 的画布 JSON、DAG 调度、RabbitMQ 任务投递、执行监控、模板市场。
- 答题时先给结论或方案，再讲关键数据结构和执行流程，最后主动说明边界、失败场景和取舍。

## 十、高频追问与参考答题要点

### 1. DAG 如何判环和排序？

先做拓扑排序。每次从入度为 0 的节点开始执行，执行完减少下游入度；如果最终可执行节点数小于总节点数，说明存在环。也可以用 DFS 三色标记。判环应该在保存、发布、加载三个入口都做，防止脏数据直接进入执行器。

### 2. 如何判断一个节点可以执行？

维护每个节点的“依赖计数”和“已就绪依赖计数”。节点完成后把结果写入上下文，再遍历出边，更新下游的就绪计数，当计数归零时投递到待执行队列。这样不会重复唤醒节点，也天然支持并行。

### 3. 节点失败重试如何保证幂等？

节点执行前生成全局唯一的执行 ID（runId + nodeId + attempt），业务副作用和状态记录使用同一个 ID。发消息、写外部系统时带上幂等键，接收方去重；数据库用唯一约束；外部系统不支持幂等时，要么先查后写，要么将操作放入事务边界内补偿。

### 4. 并行度怎么控制？

全局使用有界线程池或信号量，动态并行按批处理切分。每个批次有独立的并发限制，支持最大并发数、每批条数、失败策略（继续、停止、重试）。同时要设置整体执行时间和总节点数上限，避免失控。

### 5. LLM 节点耗时长，怎么设计？

不要在一个同步请求里完成整个工作流。执行器接收任务后异步执行，前端通过轮询或 WebSocket 获取状态。LLM 调用设置超时和流式输出，失败走重试和 fallback 模型，执行状态独立持久化，用户可随时取消。

### 6. 上下文和变量怎么设计？

上下文按 scope 分层：流程级、节点级、分支级、循环迭代级。变量可以表示为 `workflow.inputs.x`、`node_id.output.y`、`loop.item`。输出值、引用路径、执行时间、大小限制分开存储，避免一个节点的超大结果拖垮整个流程。

### 7. 版本发布和回滚怎么做？

工作流编辑时是草稿，保存后生成新版本，发布后才允许执行。执行实例绑定发布的版本快照，而不是引用可变的最新定义。回滚时发布历史版本，并把线上执行路由切到旧版本；执行中的实例继续按原版本跑完。

### 8. 前端画布和后端如何保持一致？

定义一份工作流 JSON Schema，前后端共用。前端只负责编辑和预览，保存前调用后端校验；后端校验包含结构合法性、环路、节点类型、必填参数、引用路径和 Schema 兼容性。执行器对输入定义再次校验，形成“画布、存储、执行”三层防线。

### 9. 如何统计成本？

在节点执行结束时记录模型、Token 用量、耗时、状态和费用，按工作流、用户、团队、时间维度聚合。实时统计用 Redis 累加，最终数据落 PostgreSQL，展示层提供明细和汇总两类接口。对模型调用加配额，防止异常流程消耗预算。

### 10. 多租户怎么隔离？

至少分三层：数据隔离（按 tenant_id 过滤所有查询）、执行隔离（并发配额、线程池或队列隔离）、配置隔离（模型供应商、密钥、权限）。设计上避免在业务代码里到处传租户 ID，统一从登录上下文或请求头注入。

### 11. MCP 工具如何接入？

把 MCP 工具看作一种特殊节点类型。节点配置包含工具标识、参数映射和认证方式；执行时由工具层统一调用 MCP server，再把结果转成标准 JSON 放回上下文。MCP 连接要支持复用、超时、鉴权和失败降级。

### 12. 人工审批节点怎么实现？

节点执行到审批时进入 WAITING 状态，持久化审批任务；审批接口通过后更新任务并继续推进流程，拒绝则走拒绝分支。要支持超时自动升级、撤回、转办、会签，以及第三方系统通过回调异步完成审批。

### 13. 条件表达式怎么设计？

提供受限表达式语言，只允许字段引用、比较、逻辑运算、内置函数和常量，不支持任意函数调用和代码执行。服务端做白名单解析和最大执行时间限制，避免把用户输入直接拼接成代码执行。

### 14. 分布式环境下如何避免重复执行？

任务带上全局唯一 ID，MQ 消费和数据库更新放在同一去重链路：先通过唯一约束或 Redis SETNX 抢占执行权，成功后更新状态，失败则进入重试。执行器需要幂等，状态机转移也做乐观锁，防止两个实例同时推进同一个流程。

### 15. 可观测性怎么做？

从网关进入时就生成 Trace ID，贯穿工作流、节点、日志、外部调用和数据库操作。执行日志同时记录节点 ID、输入摘要、输出摘要、耗时和错误栈。监控项包括运行量、成功率、节点耗时、队列积压、模型成本、超时和重试次数。
