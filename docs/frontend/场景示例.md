## 二、场景一：智能客服工作流

### 2.1 业务背景

**场景描述**：小美是某电商公司的客服负责人，需要处理大量重复的客户咨询。通过喵流创建一个智能客服工作流，自动分类客户问题并分流处理。

**需求分析**：
- 接收来自网站的客户咨询（Webhook触发）
- AI自动分类问题类型（发货问题/退款问题/产品咨询）
- 根据分类自动回复或转人工
- 复杂问题发送钉钉通知给客服

### 2.2 工作流设计

```
┌─────────┐    ┌────────┐    ┌─────────┐    ┌─────────────┐
│ Webhook │───▶│ AI分类 │───▶│ 条件分支 │───│ 简单回复   │
│ 触发器  │    │        │    │          │   │ (自动回复) │
└─────────┘    └────────┘    └────┬─────┘   └─────────────┘
                                  │
                    ┌─────────────┼─────────────┐
                    │             │             │
                    ▼             ▼             ▼
              ┌──────────┐  ┌──────────┐  ┌──────────┐
              │ 发货问题 │  │ 退款问题 │  │ 产品咨询 │
              │ (转人工) │  │ (转人工) │  │ (知识库) │
              └────┬─────┘  └────┬─────┘  └────┬─────┘
                   │             │             │
                   ▼             ▼             ▼
              ┌──────────┐  ┌──────────┐  ┌──────────┐
              │ 钉钉通知 │  │ 钉钉通知 │  │ 知识库检索 │
              │ (发货组) │  │ (售后组) │  │  + 自动回复│
              └──────────┘  └──────────┘  └──────────┘
```

### 2.3 前端实现

#### 2.3.1 创建工作流

```typescript
// 在编辑器中创建工作流
async function createCustomerServiceWorkflow() {
  // 1. 创建基础工作流
  const workflow = await workflowApi.create({
    name: '智能客服工作流',
    description: '自动分类客户问题并分流处理',
    category: 'customer-service',
  });

  // 2. 添加节点
  const nodes = [
    {
      id: 'trigger-1',
      type: 'webhook',
      category: 'trigger',
      title: '接收咨询',
      position: { x: 300, y: 50 },
      config: {
        method: 'POST',
        path: '/webhook/customer-service',
      },
      output: {
        variables: [
          { name: 'query', type: 'string', description: '客户问题' },
          { name: 'customerId', type: 'string', description: '客户ID' },
        ],
      },
    },
    {
      id: 'ai-classify',
      type: 'classify',
      category: 'ai',
      title: 'AI问题分类',
      position: { x: 300, y: 180 },
      config: {
        model: 'gpt-4o',
        temperature: 0.3,
        categories: [
          { id: 'shipping', name: '发货问题', description: '询问发货时间、物流状态等' },
          { id: 'refund', name: '退款问题', description: '申请退款、退货等' },
          { id: 'product', name: '产品咨询', description: '产品功能、使用方法等' },
        ],
        systemPrompt: '你是一个电商客服问题分类助手，根据客户的问题将其分类为：发货问题、退款问题或产品咨询。',
      },
      input: {
        variables: [
          { name: 'query', type: 'string' },
        ],
      },
      output: {
        variables: [
          { name: 'category', type: 'string', description: '问题分类ID' },
          { name: 'categoryName', type: 'string', description: '问题分类名称' },
        ],
      },
    },
    {
      id: 'condition',
      type: 'condition',
      category: 'flow',
      title: '问题分流',
      position: { x: 300, y: 310 },
      config: {
        branches: [
          { id: 'shipping', label: '发货问题' },
          { id: 'refund', label: '退款问题' },
          { id: 'product', label: '产品咨询' },
        ],
      },
    },
  ];

  // 3. 添加边
  const edges = [
    { id: 'e1', source: 'trigger-1', target: 'ai-classify' },
    { id: 'e2', source: 'ai-classify', target: 'condition' },
  ];

  // 4. 保存工作流
  await workflowApi.update(workflow.id, { nodes, edges });

  return workflow;
}
```

  webhook: '',

  content: {
    title: '新客服工单',
    text: `## 新客服工单\n\n**客户ID**: {{customerId}}\n**问题类型**: {{categoryName}}\n**问题描述**: {{query}}`,
  },

const availableVariables = [
  { name: 'customerId', type: 'string', description: '客户ID' },
  { name: 'categoryName', type: 'string', description: '问题分类名称' },
  { name: 'query', type: 'string', description: '客户问题' },
];

function insertVariable(path: string) {
  config.value.content.text += `{{${path}}}`;
}

const renderPreview = computed(() => {
  // 简单的变量替换预览
  let text = config.value.content.text;
  availableVariables.forEach(v => {
    text = text.replace(new RegExp(`{{${v.name}}}`, 'g'), `[${v.description}]`);
  });
  return text.replace(/\n/g, '<br>');
});
</script>

## 三、场景二：每日爆款商品分析

### 3.1 业务背景

**场景描述**：小王是某电商公司的运营，需要每天早上9点自动分析昨日销售数据，生成爆款商品报告，并发送至钉钉群。

**需求分析**：
- 定时触发（每天9点）
- 调用内部API获取销售数据
- AI分析爆款商品
- 发送钉钉群消息

### 3.2 工作流设计

```
┌─────────┐    ┌────────┐    ┌─────────┐    ┌────────┐
│ 定时触发 │───▶│ HTTP   │───▶│ AI总结  │───▶│ 钉钉   │
│ (每天9点)│    │ 请求   │    │         │    │ 通知   │
└─────────┘    └────────┘    └─────────┘    └────────┘
                      │              │
                      ▼              ▼
               获取昨日销售    分析爆款商品
                 数据          生成报告
```

不同场景可以复用相同的节点类型，只需要调整配置：

```typescript
// 钉钉通知节点在不同场景的配置差异
const dingtalkConfigs = {
  // 场景一：客服通知
  customerService: {
    webhook: 'https://oapi.dingtalk.com/robot/send?access_token=xxx',
    msgType: 'markdown',
    content: {
      text: `## 新客服工单\n**客户**: {{customerId}}\n**问题**: {{query}}`,
    },
  },

  // 场景二：数据报告
  dailyReport: {
    webhook: 'https://oapi.dingtalk.com/robot/send?access_token=yyy',
    msgType: 'markdown',
    content: {
      text: `## 每日爆款报告\n**日期**: {{date}}\n**销售额**: ¥{{totalAmount}}`,
    },
  },
};
```

## 五、总结

### 5.1 前端实现要点

1. **工作流编辑器**：通过拖拽节点、配置属性、连接边来构建工作流
2. **节点配置面板**：根据节点类型动态渲染配置表单
3. **变量系统**：实现节点间的数据传递和引用
4. **执行监控**：通过日志面板实时展示执行状态
5. **Webhook触发**：提供可调用URL供外部系统触发
