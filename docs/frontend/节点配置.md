# 工作流节点配置文档

> 喵流 (MeowFlow) 工作流节点库参考手册,涵盖全部内置节点及配置方式

---

## 一、节点架构

### 1.1 节点组成

每个工作流节点由以下部分组成:

```
┌──────────────────────────────────────────────────┐
│  节点 (Node)                                      │
│  ┌────────────────┐  ┌─────────────────────────┐ │
│  │  UI (画布上的   │  │  data (节点配置 JSON)   │ │
│  │  卡片/图标)     │  │  - 参数                │ │
│  │                │  │  - 输入/输出 schema     │ │
│  │                │  │  - 节点类型 ID          │ │
│  └────────────────┘  └─────────────────────────┘ │
│           │                       │               │
│           ▼                       ▼               │
│  ┌────────────────────────────────────────────┐  │
│  │  节点配置面板 (NodeConfigDispatcher)         │  │
│  │  根据 node.type 分发到对应 Config 组件      │  │
│  └────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────┘
```

### 1.2 节点引用配置

AI 节点和通知节点不再硬编码 API Key,而是引用 **系统设置** 中预先配置的资源:

```
系统设置 (Settings.vue)
   ├── LLM 模型表 (mf_ai_model)         → 节点 modelId
   └── 集成配置表 (mf_integration_config) → 节点 integrationId
```

工作流节点配置只保存 ID,密钥由后端在执行节点时按 ID 解密使用,前端展示始终脱敏。

## 二、节点分类

| 类别 | 说明 |
|------|------|
| **trigger** | 触发器 - 工作流入口 |
| **ai** | AI 节点 - 调用 LLM / Agent |
| **flow** | 流程节点 - 控制流 (条件/循环/聚合) |
| **tool** | 工具节点 - HTTP/数据库/代码/自定义 |
| **notify** | 通知节点 - 钉钉/企微/飞书/邮件/短信 |

## 三、内置节点详解

### 3.1 触发器 (trigger)

#### `trigger.webhook` - Webhook 触发器

通过 HTTP 请求触发工作流。

**参数**:
- `method` - 请求方法 (GET/POST/PUT)
- `path` - 路径,如 `/hooks/incoming`
- `authToken` - 认证 Token (可选)

**输出**: `body`(请求体)、`method`、`path`

#### `trigger.cron` - 定时触发器

通过 Cron 表达式定时执行。

**参数**:
- `cron` - Cron 表达式,如 `0 0 * * *`
- `timezone` - 时区,默认 `Asia/Shanghai`

**输出**: `time`(触发时间)

#### `trigger.form` - 表单触发器

用户提交表单时触发。

**参数**:
- `formId` - 表单 ID
- `fields` - 字段定义 (JSON)

#### `trigger.imessage` - 消息触发器

接收钉钉/企微/飞书消息触发。

**参数**:
- `platform` - 平台 (dingtalk/wxwork/feishu)
- `keyword` - 触发关键词

### 3.2 AI 节点 (ai)

#### `ai.llm` - LLM 对话 (引用模型)

调用大语言模型进行对话。**模型通过下拉框从系统设置中选取**。

**关键参数**:
- `modelId` - 引用的模型 ID(从系统设置获取)
- `prompt` - 用户 Prompt
- `systemPrompt` - 系统提示词
- `temperature` - 温度 (0-2)
- `maxTokens` - 最大 Token
- `outputName` - 输出变量名

**输出**: `text`(生成文本)、`tokens`(Token 数)

#### `ai.classify` - AI 分类

对输入文本进行分类。

**参数**:
- `modelId` - 模型 ID
- `categories` - 候选类别 (含 id/name/description)
- `input` - 输入文本变量
- `systemPrompt` - 分类指令

#### `ai.agent` - Agent 智能体 (新)

> 参考 Dify 的 Agent Node 设计,让 LLM 自主选择调用工具

**关键参数**:
- `modelId` - 驱动 Agent 的模型
- `strategy` - 推理策略:
  - `function-calling` - 通过模型原生工具调用 (推荐 GPT-4 / Claude 3.5+)
  - `react` - ReAct (Thought → Action → Observation 循环)
- `tools` - 可用工具列表 (逗号分隔的工具 ID)
- `instruction` - Agent 指令 (支持 Jinja 语法)
- `query` - 用户查询
- `maxIterations` - 最大迭代次数

**输出**:
- `text` - 最终答案
- `toolOutputs` - 工具调用结果列表
- `reasoning` - 推理轨迹 (尤其 ReAct 模式)
- `iterations` - 实际迭代次数

**示例**:

```yaml
strategy: function-calling
instruction: |
  你是技术支持助手,使用工具帮用户解决问题。
  当前用户: {{trigger.user}}
tools: web-search,calculator,email-sender
query: "{{trigger.message}}"
maxIterations: 5
```

#### `ai.parameter-extractor` - 参数提取 (新)

> 从自然语言抽取结构化参数

**参数**:
- `modelId` - 模型 ID
- `schema` - JSON Schema,定义要抽取的字段
- `text` - 输入文本变量
- `instruction` - 提取指令

**示例**:

```json
{
  "schema": {
    "name": "string",
    "age": "number",
    "skills": ["string"]
  }
}
```

#### `ai.question-classifier` - 问题分类 (新)

> 基于 LLM 的多分类路由

**参数**:
- `modelId` - 模型 ID
- `categories` - JSON 数组,如 `["技术支持","销售咨询","投诉建议"]`
- `query` - 待分类问题
- `instruction` - 分类指令

### 3.3 流程节点 (flow)

#### `flow.condition` - 条件分支

单一条件 if/else 判断。

**参数**:
- `expression` - 条件表达式,例 `{{input.score}} >= 80`

**输出**: `true`、`false` 两个分支

#### `flow.if-else` - IF/ELSE 多条件 (新)

> 参考 Dify 的 If/Else 节点,支持多个独立分支条件

**参数**:
- `cases` - 分支列表 (JSON 数组)

```json
[
  {"id": "c1", "name": "优秀", "expression": "{{input.score}} >= 80"},
  {"id": "c2", "name": "及格", "expression": "{{input.score}} >= 60"},
  {"id": "c3", "name": "不及格", "expression": "true"}
]
```

#### `flow.iteration` - 迭代 (新)

> 遍历数组,对每项执行子流程(支持嵌套)

**参数**:
- `source` - 数据源路径,如 `{{upstream.items}}`
- `iterator` - 迭代变量,默认 `item`
- `outputType` - 输出类型 (array / flatten)
- `parallel` - 并行执行(实验性)
- `errorMode` - 错误处理 (abort / skip / continue)

**输出**: `results` - 所有迭代结果

#### `flow.aggregation` - 结果聚合 (新)

> 将多条分支的输出合并为单一结果

**参数**:
- `strategy` - 聚合策略:
  - `concat` - 拼接(可指定 separator)
  - `merge` - 合并对象
  - `first` / `last` - 取首/末
- `branches` - 分支输入列表

#### `flow.template-transform` - 模板转换 (新)

> Jinja/Mustache 语法的字符串模板

**参数**:
- `template` - 模板内容,使用 `{{var}}` 引用变量

**示例**:

```
你好, {{user.name}}! 今天是 {{date}}.
您的订单 #{{order.id}} 状态: {{order.status}}
```

#### `flow.loop` - 循环

支持 For/While 循环。

**参数**:
- `iterator` - 迭代变量,默认 `{{items}}`

### 3.4 工具节点 (tool)

#### `tool.http` - HTTP 请求

**参数**:
- `method` - 方法 (GET/POST/PUT/DELETE)
- `url` - URL
- `headers` - Headers (JSON)
- `body` - Body (JSON)

#### `tool.list-operator` - 列表操作 (新)

> 对数组进行过滤/映射/规约/排序等操作

**参数**:
- `operation` - 操作类型:
  - `filter` - 过滤 (`item.score > 0.5`)
  - `map` - 映射 (返回新对象)
  - `reduce` - 规约 (返回累加值)
  - `sort` - 排序 (配合 `sortKey` 和 `sortOrder`)
  - `first` - 取首项
  - `unique` - 去重
  - `count` - 计数
- `expression` - 表达式(filter/map/reduce 使用)
- `sortKey` - 排序键
- `sortOrder` - 升降序

#### `tool.variable-assigner` - 变量赋值 (新)

> 一次设置多个变量,支持覆盖已存在

**参数**:
- `assignments` - 赋值列表 (JSON 数组)
- `overwrite` - 是否允许覆盖

**示例**:

```json
[
  {"name": "foo", "value": "{{llm.text}}"},
  {"name": "bar", "value": 42}
]
```

#### `tool.document-extractor` - 文档提取 (新)

> 从 PDF/Word/Excel 中提取文本

**参数**:
- `fileUrl` - 文件 URL
- `fileType` - 文件类型 (auto/pdf/docx/xlsx/md/txt)
- `extractMode` - 提取模式 (full / by-page)
- `ocr` - 是否启用 OCR
- `maxChars` - 最大字符数

#### `tool.code` - 代码执行

**参数**:
- `language` - JavaScript / Python
- `source` - 代码

#### `tool.assign` - 变量赋值 (单变量)

#### `tool.abstract` - 自定义节点 (新,自由开发)

> 通过参数定义 + 代码,自由创建节点行为

**配置面板 (Tabs)**:

1. **参数定义**:代码语言、输入/输出 JSON Schema、超时
2. **执行代码**:编写 JavaScript / Python 代码
3. **测试运行**:输入示例,本地预览输出

**执行约定**:
- 上游以 `input` 对象形式注入
- 代码返回值作为 `output` 传递给下游
- 支持超时控制 (5-300 秒)
- 沙箱执行,不污染全局

**示例 (JavaScript)**:

```javascript
// input 为上游注入的对象
const text = input.text || '';
const count = input.count || 10;
const result = text.substring(0, count);
return { result };
```

**示例 (Python)**:

```python
import json
input = json.loads(input_json)
result = {"result": input["text"][:input["count"]]}
print(json.dumps(result))
```

### 3.5 通知节点 (notify)

> 通知节点引用**集成配置**(`integrationId`),通过下拉框选择已配置的通知集成。

#### `notify.dingtalk` - 钉钉通知

**关键参数**:
- `integrationId` - 引用系统设置中的钉钉集成
- `text` - 消息内容(支持 `{{var}}` 引用)
- `atMobiles` - @手机号(可选)

#### `notify.wxwork` / `notify.feishu` - 企微/飞书

参数与钉钉类似。

#### `notify.email` - 邮件

#### `notify.sms` - 短信

## 四、节点变量引用

### 4.1 表达式语法

节点配置中所有文本字段支持 `{{...}}` 表达式:

| 语法 | 说明 |
|------|------|
| `{{trigger.query}}` | 触发器输入 |
| `{{llm.text}}` | 上游节点输出 |
| `{{user.name}}` | 嵌套对象访问 |
| `{{items[0]}}` | 数组索引 |

### 4.2 VariablePicker 组件

每个节点配置面板通常包含 **VariablePicker**,可弹出变量树,点选即可插入。

## 五、添加自定义节点

### 5.1 编辑器节点目录

`src/mock/nodes.ts` 中追加节点定义:

```typescript
{
  type: 'tool.my-custom',
  category: 'tool',
  classification: 'processing',
  name: '我的自定义',
  icon: 'fa-star',
  color: '#a855f7',
  description: '节点描述',
  inputs: [{ key: 'in', label: '输入', type: 'string' }],
  outputs: [{ key: 'out', label: '输出', type: 'string' }],
  params: [
    { key: 'foo', label: 'Foo', type: 'string', required: true },
  ],
},
```

### 5.2 配置组件

`src/components/workflow/config/MyCustomConfig.vue`:

```vue
<template>
  <el-form label-width="100px" size="small">
    <el-form-item label="Foo" required>
      <el-input :model-value="modelValue?.foo"
        @update:model-value="(v) => patch({foo: v})" />
    </el-form-item>
  </el-form>
</template>

<script setup lang="ts">
const props = defineProps<{ modelValue: Record<string, any> }>();
const emit = defineEmits<{
  (e: 'update:modelValue', v: Record<string, any>): void;
}>();
function patch(extra: Record<string, any>) {
  emit('update:modelValue', { ...props.modelValue, ...extra });
}
</script>
```

### 5.3 注册到分发器

`src/components/workflow/config/NodeConfigDispatcher.vue`:

```typescript
import MyCustomConfig from './MyCustomConfig.vue';

// 在 template 中
<MyCustomConfig
  v-else-if="node.type === 'tool.my-custom'"
  :model-value="configValue"
  @update:model-value="emitChange"
/>
```

## 六、最佳实践

1. **引用而非硬编码** - 节点通过 `modelId` / `integrationId` 引用系统设置中的配置,便于集中管理密钥
2. **合理设置超时** - 抽象节点、HTTP 节点必须设置超时,避免长时间阻塞
3. **利用变量插入** - 优先使用 VariablePicker 插入 `{{...}}`,而非手写
4. **Agent 谨慎使用** - Agent 节点消耗 Token 较多,需合理设置 `maxIterations`
5. **错误处理** - 关键节点配置 `errorMode` 或兜底分支,避免工作流中断
